# HITRUST CSF

**Where:** `docs/compliance/hipaa-hitrust-mapping.md`. HITRUST is a certifiable framework that harmonizes HIPAA, NIST, ISO 27001 and others into control requirements; hospitals use it (or a questionnaire derived from it) to judge vendors. We do **not** get certified in this course; we learn to *speak it* and to evidence controls.

## Learning objectives
1. Read the CSF's structure: control categories (access control, audit logging, incident management, third-party assurance, ...) and assurance levels.
2. Answer the five questions every reviewer asks, with evidence: encryption, unauthorized access, recording of access and changes, incident response, third-party vendors.
3. Build an honest **control mapping**: Implemented / Partial / Customer / Gap, with a file or test for every "Implemented".
4. Understand the difference between *having a control* and *being able to prove it to a stranger*.

## Exercise (60 minutes): map one feature to controls
Take "break-the-glass". Fill: what risk it addresses; HIPAA citation (164.312(a)(2)(ii)); CSF area; implementation (file); test; operational evidence (alert, review queue); gap (who reviews at 2 a.m.?). Then do the same for "de-identification before the model".

## Discussion
* Why do assessors prefer evidence that is *generated by the system* (an audit chain verification) to a policy document?
* Which of our "Customer" rows would you push back on, and what would you offer to take on?
* What is the cheapest control with the largest assurance? (Often: a test that runs on every commit and a dashboard the customer can open.)

## Pitfalls
Mapping without evidence; claiming a framework you are not assessed against; treating the gaps list as an embarrassment instead of the most credible page in the pack.
